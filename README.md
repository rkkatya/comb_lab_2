# Лабораторная работа 2. Схемы широковещательного шифрования

Комбинаторный анализ, 8 семестр

## Как запустить

```
python3 broadcast.py
```

Ничего ставить не надо, работает на стандартном питоне. По времени -- минут 10-15 на обычном ноуте (если хочется быстрее, можно уменьшить `N_SAMPLES` в начале файла).

## Суть задачи

Есть n=1000 абонентов, они сидят в листьях полного бинарного дерева. Каждому внутреннему узлу соответствует ключ шифрования. Когда часть абонентов отзывают (компрометируют), нужно построить покрытие -- набор поддеревьев, которые целиком состоят из неотозванных абонентов. Размер покрытия = сколько ключей нужно использовать для шифрования.

Это схема NNL Complete Subtrees (Naor-Naor-Lotspiech).

## Задание 1

Для каждого r (от 10% до 90% абонентов) генерируем случайные подмножества отозванных и считаем среднее по размеру покрытия.

Дерево я храню неявно -- листья это числа от 0 до 1023 (ближайшая степень двойки к 1000, лишние 24 листа считаются фантомными). Покрытие считаю обходом сверху вниз: если в поддереве нет отозванных -- это один элемент покрытия, если все отозваны -- пропускаем, иначе рекурсивно идем в детей.

Для быстрого подсчета числа отозванных в поддереве использую бинарный поиск (bisect) по отсортированному списку отозванных. Получается довольно быстро -- дерево глубины 10, и большинство ветвей обрезаются рано.

В задании написано N=1,000,000 выборок, но в чистом питоне это часа два. Я поставила N=100,000 -- этого хватает для нормальной точности (± 0.5 от теоретического значения).

## Задание 2*

Теоретическая оценка матожидания. Каждый узел v (кроме корня) попадает в покрытие, если в его поддереве нет отозванных, а в поддереве его брата есть хотя бы один. Вероятность этого:

```
P(v в покрытии) = C(n - s_v, r)/C(n, r) - C(n - s_parent, r)/C(n, r)
```

где s_v -- число реальных абонентов в поддереве v. Суммируем по всем узлам и получаем точное E[покрытия]. Считаю через логарифмы биномиальных коэффициентов (lgamma), чтобы не было переполнения.

Теоретические значения и монте-карло сходятся с точностью до десятых.

## Результаты

Покрытие максимально при r ~ 300 (30% отозванных), а не при 50% как можно было бы подумать. Это потому что при r > n/2 отозванных слишком много и покрывать уже почти некого -- свободных абонентов мало. А при малых r большие поддеревья целиком свободны и покрываются одним ключом.

Примерные значения:
- r=100 (10%): покрытие ~ 265
- r=300 (30%): покрытие ~ 388 (максимум)
- r=500 (50%): покрытие ~ 359
- r=900 (90%): покрытие ~ 95
